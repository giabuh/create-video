# Remotion vs HyperFrames — pilot comparison (design)

## Goal
Render one real reel with HyperFrames next to a fresh Remotion render of the same storyboard, so the user can see
and judge which engine is better. Criteria chosen by the user: **A** visual/motion quality, **B** render speed on
this machine, **D** stability. Not in scope: **C** editing workflow, app integration.

## Decisions
- **Project:** `projects/2026-11-20-demo-card-moi` (26.7 s, 5 scenes, fade transitions, 2/2/2/1/1 clips, music,
  6 sfx, no video-wide overlays; motion `OfferCard`, `Checklist`, `Stamp`, `Picture`; CTA 3 s).
- **Baseline is a fresh Remotion render**, not `reel-v2`. `storyboard.json` changed after v2, and v1–v3 predate the
  NVENC 12 Mbps encode (they are about 6.5 Mbps). The baseline is the next app render (`reel-v4`) of the current
  storyboard, made through the app's real render job.
- **HyperFrames runs locally only.** No HeyGen cloud (its MCP compose/render tools are disabled in Claude Code, and
  footage must not leave the machine). Telemetry is turned off if the CLI has any.
- **Machine:** RTX 5060 Ti 16 GB (this machine). The GTX 1650 home machine is not measured.
- **Isolation:** no changes to `app/`, `studio/` or `app/server/render.ts`. The user's uncommitted change in
  `projects/2026-11-20-demo-card-moi/project.json` is left alone. The app writes that file itself when it renders
  or deletes a version, which is fine.
- **HyperFrames authoring guidance** is installed with `npx skills add heygen-com/hyperframes` (user approved).
  It adds skill files and edits `skills-lock.json`.

## Layout
- `tools/hyperframes/package.json`: pins the exact `hyperframes` CLI version (and GSAP if not bundled).
- `tools/hyperframes/build.mjs`: generator, `node tools/hyperframes/build.mjs projects/<slug>`. It writes
  `projects/<slug>/hyperframes/index.html` from `render-props.json`.
- `projects/<slug>/hyperframes/cards/`: hand-written card code (JS/CSS) that `index.html` includes.
- `projects/<slug>/hyperframes/assets/`: copied or linked footage, fonts, GSAP, baseline audio. Git-ignored.
- `projects/<slug>/compare/`: bench outputs, side-by-side video and frame pairs. Git-ignored, since it holds student
  footage.
- `docs/reports/2026-11-21-remotion-vs-hyperframes.md`: the results report (committed; text and tables only, it
  refers to images in `compare/` by path).

## Composition: generated vs hand-written
HyperFrames' timing compiler reads `<video>`/`<audio>` clips statically from the HTML, so every media clip must be
in the file, not created by JS. Clips on one track cannot overlap in time.

**Generated by `build.mjs` from `render-props.json`:**
- Root composition 1080×1920 at `fps`, length `totalSeconds`.
- One `<video>` per `MediaItem`: `start`, `duration`, source offset `from` (use the exact HyperFrames attribute for
  the media start offset, taken from its docs, not guessed), `effect` (zoom/pan) as GSAP tweens, and the blurred
  background fill the Remotion `MediaShot` draws behind the clip.
- Scene and clip `fade` transitions: clips alternate between two tracks so the overlap is allowed; opacity tweens of
  `transitionSeconds`.
- Captions: each `CaptionChunk` (`text`, `start`, `end`) with the `highlight` words, the `captions` style
  (font, size, color, highlight color, `box`), and the same auto-fit to the safe area as the Remotion `Captions`.
- Audio: one `<audio>` clip with the baseline's audio track extracted to WAV (voice, music ducking and sfx stay
  identical). HyperFrames' own audio mixing is therefore not tested; the report says so.

**Hand-written in `cards/`:** the motion layers this project uses (`OfferCard`, `Checklist`, `Stamp`, `Picture`)
and the CTA card. Content, brand colors, fonts, layout, placement and timing (`start`, `duration`, position/box,
voice-synced items) match the Remotion versions; text is copied verbatim from `render-props.json` (CLAUDE.md
rule 1). Only the motion is written the GSAP-idiomatic way, following the installed HyperFrames skills. This keeps
the comparison about the engines, not about two different designs.

**Assets:** GSAP is vendored locally (no CDN at render time). Fonts are the same files `studio/` uses, loaded with
`@font-face`; Vietnamese diacritics are checked in a still. Footage is referenced in place if HyperFrames can read
paths outside its project directory (checked in the spike); otherwise only the clips used are copied into `assets/`.

## Step 1: go/no-go spike
Before any authoring: install the pinned CLI and skills, run `hyperframes doctor`, then render a tiny composition
(one real footage clip from this project, one audio clip, one Vietnamese text line) with
`--gpu --browser-gpu --video-bitrate 12M`. It must show that:
- NVENC encode works with the ffmpeg HyperFrames uses;
- Chrome really uses the GPU (no silent SwiftShader fallback);
- the footage path resolves (in place, or after copying);
- Vietnamese text renders with the studio font;
- telemetry is off (how it was turned off is recorded);
- VFR or sparse-keyframe warnings, if any, are noted.

If any of these fails and cannot be fixed with a flag or config, stop and report to the user before going further.

## Measurements
All timed runs happen on an otherwise idle GPU: no other render, spike or authoring job runs at the same time. The
app's TTS worker stays resident, as in normal use.

**B: speed**
- Remotion: 3 sequential app render jobs (`POST /projects/<slug>/render`, the real chunked path: 3 chunks × 2 tabs,
  NVENC 12 Mbps, Vulkan). Time = job `endedAt − startedAt`. Report the first run separately (cold: bundle may
  rebuild) and the median of all 3. The job also includes the voice check (cached audio), which the report notes.
  The extra versions these runs create are deleted afterwards through the app (`DELETE /projects/<slug>/renders/<v>`),
  keeping only the baseline `reel-v4`.
- HyperFrames: `hyperframes render --gpu --browser-gpu --video-bitrate 12M`, a short worker sweep (one run each at
  auto, 2, 4, 6; or `hyperframes benchmark`), then 3 sequential timed runs at the best setting. Wall clock of the
  CLI. First run reported separately, then the median.
- Both outputs are checked with ffprobe to be the same spec: 1080×1920, 30 fps, h264, about 12 Mbps, same frame
  count (`round(totalSeconds × fps)`). Without this, timings are not comparable.

**A: visual/motion**
- `compare/side-by-side.mp4`: Remotion on the left, HyperFrames on the right, baseline audio.
- Frame pairs (same timestamp from both) at the middle of every scene, at each card's entrance and exit, and in the
  CTA.
- Expectation stated in the report: both engines rasterize in headless Chrome, so text and card sharpness are equal
  by construction. Real differences: motion feel, footage frame handling (seek accuracy, blur fill), encode.

**D: stability** (same checks on both engines; reported as observations, since one 27 s video is a small sample)
- Exit code and warnings of every run.
- Frame count and duration against the expected values.
- `blackdetect` and `freezedetect` on each output.
- Frames at every scene boundary (±1 frame) compared between the two engines.
- Run-to-run consistency: the same frames decoded from two runs of one engine compared with PSNR/SSIM
  (encodes are lossy, so a byte hash would always differ).

## Outputs shown to the user
- In the app (**Bản render**): `reel-v4.mp4` = Remotion baseline, `reel-v5.mp4` = HyperFrames final (the next
  free number after the bench deletions; the report states which number is which engine). The HyperFrames version
  has no `reel-v5.storyboard.json` snapshot; it is not a storyboard version. `versions.ts` lists any
  `reel-vN.mp4`; this is confirmed in the app.
- `compare/side-by-side.mp4` and the frame pairs.
- The report: speed table, spec check, stability observations, visual notes, limits of the test.

## Error handling
- Spike failure: stop and report (above).
- A HyperFrames run that fails or warns is recorded as a stability observation, not retried silently; retries are
  counted in the report.
- Bench runs never overwrite a version: renders go to `compare/` first, and only the final HyperFrames file is
  copied to the next free `reel-vN.mp4`.

## Out of scope
An engine option in the app, porting the other motion components, HyperFrames Studio preview, HyperFrames audio
mixing, criterion C, the GTX 1650 machine, HeyGen cloud.

## Done
`reel-v4` (Remotion) and `reel-v5` (HyperFrames) play in **Bản render**; `compare/` holds the side-by-side video and
frame pairs; the report exists with all measurements above; `app/`, `studio/` and `render.ts` are unchanged; the
existing tests still pass.
