# In-app Claude chat (Sub-project 3, part A) — Design

Date: 2026-11-19
Status: approved in brainstorming, pending written-spec review
Parent: `2026-11-18-reel-pipeline-design.md` (roadmap item 3). App: `2026-11-18-reel-app-design.md`.

## Goal

Chat with Claude Code from inside the reel app, so the user can ask for reel work ("làm video cho khóa IELTS", "đổi cảnh 3") without a terminal. The app runs the local `claude` CLI headless in the repo root under the user's own logins and lets the user pick the account (`claude`, `claude2`, `claude3`) per chat, so a chat that hits a usage limit can continue on another account. Personal, single-user, localhost only.

Part B (later, separate spec/plan): a `codex exec --json` backend behind the same runner interface.

## Decisions

- **One process per turn** (approach A). Each send spawns `claude -p --output-format stream-json --verbose --include-partial-messages --dangerously-skip-permissions` with cwd = repo root. Rejected: a long-lived `--input-format stream-json` process per chat (account switch needs a restart, idle-process lifecycle, does not map to codex) and the Claude Agent SDK (extra dependency; the parent spec fixes "run the local CLI"). Cost: ~2–3 s startup per turn (SessionStart hooks still run headless).
- **Permissions: `--dangerously-skip-permissions`**, same as the user's `claude2`/`claude3` shell functions. Protection is the existing `hostGuard` + binding to 127.0.0.1. The app must never be exposed beyond localhost.
- **UI: a global slide-over panel**, opened from a Chat button in the top bar, available on every screen.
- **History: only chats created in the app**, stored by the app. Terminal sessions are not listed (no parsing of Claude Code's internal transcript format).
- **Usage limit: notify + one-click switch.** No automatic failover.
- **One running turn at a time across the whole app.** Other chats can be viewed but not sent to while a turn runs.

## Accounts

Detected by the server at request time (cheap directory checks), never configured by hand:

| name | env |
|---|---|
| `claude` | `CLAUDE_CONFIG_DIR` **removed** from the child env (the app may have been started from a `claude2` shell) |
| `claude<N>` | `CLAUDE_CONFIG_DIR=~/.claude-acc<N>`, for each `~/.claude-acc<N>` (N = digits) that has `.credentials.json` **and** whose `projects` is a symlink resolving to `~/.claude/projects` |

An account dir that fails the symlink check is skipped (its transcripts are not shared, so resume across accounts would fail). The app does not re-run the bashrc `_claude_acc` symlink sync; `claude<N>` in a terminal keeps doing that.
shortcut: home dir is `os.homedir()`; tests override it via an env var (e.g. `REEL_CLAUDE_HOME`).

Each account carries the latest `rate_limit_info` seen in its stream (`status`, `resetsAt`, `utilization`, `rateLimitType`), kept in memory only, so the picker can show e.g. `claude2 · 56%`. Unknown until the account has run a turn since the server started.

## Runner (shared interface for part B)

```ts
type ChatEvent =
  | {kind: 'user'; text: string; account: string; at: number}
  | {kind: 'delta'; text: string}                       // live only, never persisted
  | {kind: 'text'; text: string}                        // a complete assistant text block
  | {kind: 'tool'; name: string; summary: string}       // e.g. "Bash: python3 tools/prepare.py …", "Edit: projects/x/storyboard.json"
  | {kind: 'done'; costUsd: number | null; durationMs: number | null}
  | {kind: 'error'; message: string; limit?: {account: string; resetsAt: number | null}};

runTurn(opts: {sessionId: string; resume: boolean; account: Account; prompt: string;
               systemAppend: string; signal: AbortSignal; onEvent(e: ChatEvent): void}): Promise<void>
```

- First turn of a chat: `--session-id <uuid generated by the app>`; later turns: `--resume <sessionId>`. The chat is marked `started` once the stream's `system/init` event arrives; `resume` = `started`.
  shortcut: if a turn dies before `init`, the next turn retries with `--session-id`; if Claude reports the session missing on `--resume`, the turn ends in `error` (no auto-recovery).
- The prompt is written to the child's stdin (never argv: text may start with `-`).
- `--append-system-prompt` on every turn: the user is chatting from the reel app, which is running (CLAUDE.md rule 10), plus the screen they are on and, in the Editor, `projects/<slug>`.
- Stream mapping (from a real `stream-json` capture, Claude Code 2.1.328):
  - `stream_event` with `content_block_delta`/`text_delta` → `delta`
  - `assistant` message: each `text` block → `text`; each `tool_use` block → `tool` (summary = first useful input field: `command`, `file_path`, `pattern`, `description`…, truncated to ~80 chars)
  - `rate_limit_event` → update the account's limit info; `status: "rejected"` marks the turn as limit-hit
  - `result`: `is_error` false → `done` (`total_cost_usd`, `duration_ms`); `is_error` true or limit-hit → `error`, with `limit` when limit-hit or `api_error_status` is 429
  - everything else (hooks, status, `commands_changed`, `user` tool results) is ignored
  - non-JSON lines and a non-zero exit without `result` → `error` with the last stderr line
- Abort (Stop button): kill the child (SIGTERM, then SIGKILL after 3 s) → `error: "Đã dừng"`.
- Binary path overridable by env (e.g. `REEL_CLAUDE_BIN`) so tests and E2E use a fake script.

## Server

- `ChatRunner` holds at most one active turn (app-wide). A send while busy → 409.
- Storage: `app/.data/chats/index.json` (array of `{id, sessionId, title, account, slug, started, createdAt, updatedAt}`; title = first user message, ~60 chars) and `app/.data/chats/<id>.jsonl` (append-only persisted `ChatEvent`s, no `delta`). `app/.data/` is gitignored and must stay outside the file watcher and the static routes. Chat `id` = `sessionId` (uuid).
- A chat log whose last turn has no `done`/`error` (server stopped mid-turn) is shown as interrupted.
- Routes (under `/api`, behind `hostGuard`; inputs validated: text non-empty and size-capped, account must be a detected one, id must be a known uuid):
  - `GET /chat/accounts` → `[{name, limit}]`
  - `GET /chats` → index, newest first
  - `POST /chats {slug?}` → new chat
  - `GET /chats/:id` → `{chat, events}`
  - `POST /chats/:id/messages {text, account, screen, slug?}` → 202, starts the turn; stores `account` on the chat
  - `POST /chats/:id/stop`
- Live updates over the existing SSE bus: new `ServerEvent` `{type: 'chat'; chatId: string; event: ChatEvent}` plus `{type: 'chatBusy'; chatId: string | null}`; the `/events` snapshot includes the current `chatBusy`. On SSE reconnect the client refetches `GET /chats/:id`.
- Child processes are killed when the server shuts down.

## UI

- Top bar Chat button → right slide-over (~420 px on desktop, full screen on phone), available on every screen. It reuses the app's `ui/` components and theme tokens.
- Header: chat picker (list + "Phiên mới") and account picker (detected accounts with last utilization %).
- Body: messages as `pre-wrap` text (no markdown rendering), tool events as one dim line each, live `delta` text appended to the current assistant bubble, interrupted/stopped/error states inline.
- Composer: textarea, Enter sends, Shift+Enter newline; disabled with a Stop button while any turn runs.
- Limit hit: banner "`<account>` hết limit (reset HH:mm)" with one button per other account: "Tiếp tục bằng `<other>`" → sets the chat's account and sends `Tiếp tục` on `--resume` of the same session.
- New chat records the current slug (if in the Editor) for display; each turn sends the screen/slug the user is on at send time.

## Testing

- Unit: stream parser against captured `stream-json` fixture lines (text, tool_use, rate_limit rejected, result error/success, garbage line).
- Runner: fake `claude` script via `REEL_CLAUDE_BIN` (prints fixture lines, checks it received the prompt on stdin and the expected `--session-id`/`--resume`/`CLAUDE_CONFIG_DIR`); abort kills it.
- Accounts: temp home with valid, missing-credentials and non-symlinked `projects` dirs.
- Routes: 409 while busy, validation errors, persisted jsonl excludes `delta`.
- E2E (Playwright, fake binary): open panel, send, see streamed text and a tool line, stop, limit banner → continue on another account.
- No test spends real quota.

## Out of scope

Markdown rendering, model picker, image/file attachments, deleting/renaming chats, listing terminal sessions, automatic account failover, parallel turns, permission prompts in the UI, the codex backend (part B).
